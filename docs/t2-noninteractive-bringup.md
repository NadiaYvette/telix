# T2 SDE Non-Interactive Userspace Build for Telix

## Executive Summary

T2 SDE (https://t2sde.org) is a source-based distribution build system that can produce a complete Linux userspace without a kernel—ideal for dropping on top of Telix's Linux personality. However, **the initial configuration step is fundamentally interactive** and cannot be fully automated; subsequent builds can be tuned via command-line args. This guide documents the workflow, config file format, and a strategy to minimize human interaction.

## T2 SDE Source Location

**Upstream Repository:** https://github.com/rxrbln/t2sde (MIT-licensed, actively maintained by René Müller and the T2 community)

**Recommended Clone:**
```bash
git clone --depth=1 https://github.com/rxrbln/t2sde ~/src/t2sde
# ~17k files, ~200MB. Build prereqs: gcc, make, ar, cpp, ncurses-devel.
which gcc make ar cpp && pkg-config --exists ncurses && echo "prereqs-OK"
```

## Why Interactive Bootstrap is Required

From the Telix project history (commit `ca00294`), the T2 config system works as follows:

- **Interactive mode (`./t2 config`)**: Compiles a ncurses dialog that cascades through architecture → target-type → target → packages. This runs validation rules and builds a fresh `config/NAME/config` file from scratch.
- **Args-mode (`./t2 config -cfg NAME key=val`)**: Uses `sed` to patch existing config files. **This mode is non-interactive but only works on already-populated configs.** Editing an empty file silently no-ops because there are no `SDECFG_*` lines to patch.

**Consequence:** The first time you create `config/tlx-min/`, you must run the TUI once (~30 seconds of human interaction: navigate to Target → tlx-min, press F2/Save, exit).

## Minimal Config File for Telix

After the one-time interactive bootstrap, the resulting config file at `config/tlx-min/config` contains lines like:

```bash
# Generated by ./t2 config for target tlx-min
SDECFGSET_INIT='busybox'
SDECFGSET_OPT='size'
SDECFGSET_DO_REBUILD_STAGE=0
SDECFGSET_CROSSBUILD=0
SDECFGSET_DISABLE_NLS=1
SDECFGSET_LIBC="glibc"
SDECFGSET_ARCH="x86_64"
SDECFGSET_KERNEL_FLAVOR=""
```

**Key knobs to verify post-bootstrap:**
- `SDECFGSET_LIBC="glibc"` — Telix's Linux personality has best glibc coverage (per `project_phase171_gap_a` memory note). Switch to `"musl"` only if glibc's `__intl_freemem` exit-path causes issues.
- `SDECFGSET_ARCH="x86_64"` — Target architecture. Use `"aarch64"` for ARM, but set `SDECFGSET_CROSSBUILD=1` if building on x86_64.
- `SDECFGSET_OPT='size'` — Optimizes for small payload (important for initramfs budget).
- `SDECFGSET_CROSSBUILD=0` — Same-arch native build is faster. Toggle to `1` for cross-compilation.

## Package Selection

T2's package list is stored in a separate `pkgsel` file. Telix's minimal target (at `tools/t2/targets/tlx-min/pkgsel`, synced to `target/tlx-min/pkgsel`) selects:

```
# Toolchain (built for bootstrapping, not shipped to Telix)
[O] toolchain = binutils
[O] toolchain = gmp
[O] toolchain = mpfr
[O] toolchain = gcc

# Payload (what actually ships to Telix initramfs/)
[O] payload  = 00-dirtree
[O] payload  = busybox
[O] payload  = zlib
```

**Key design decisions** (from `tools/t2/targets/tlx-min/`):
- **linux + linux-header dropped** — Telix supplies its own kernel. We only build userspace.
- **No dropbear SSH by default** — Add `[O] payload = dropbear` once Telix's network stack matures.
- **Toolchain still built** — Needed to bootstrap package compilation; these binaries are NOT shipped to Telix.

## Complete Build Workflow

### 1. One-Time Setup

```bash
# Clone T2
git clone --depth=1 https://github.com/rxrbln/t2sde ~/src/t2sde
export TELIX_T2_HOME=~/src/t2sde

# Sync Telix's tlx-min target into T2's directory structure
cd /path/to/telix
tools/t2/sync-target.sh   # copies tools/t2/targets/tlx-min/ → $TELIX_T2_HOME/target/tlx-min/
```

### 2. Interactive Configuration (One-Time, ~30 Seconds)

```bash
cd "$TELIX_T2_HOME"

# Run the ncurses config tool
./t2 config --cfg telix-min
```

**Navigation steps in the menu:**
1. When prompted for **Target**, select "Telix minimal userspace (kernel-less, glibc, busybox)" (or navigate to `tlx-min`).
2. Architecture defaults to your host (x86_64 on x86 hosts); leave it unless cross-compiling.
3. Review other options (libc, optimization, etc.) — all should match `tools/t2/targets/tlx-min/config.in` defaults.
4. Press **F2** (or equivalent Save key), then **Exit**.

This creates:
- `$TELIX_T2_HOME/config/telix-min/config` — populated with SDECFGSET_* lines
- `$TELIX_T2_HOME/config/telix-min/packages` — binary package selections from the menu

### 3. Build (Multi-Hour, First Time ~30min-2hr)

```bash
cd "$TELIX_T2_HOME"

# Kick the build. T2 builds toolchain first, then payload packages.
./t2 build -cfg telix-min

# Monitor progress in build/telix-min-*/
# Output artifact: build/telix-min-*/rootfs/ (unified filesystem tree)
```

### 4. Merge into Telix Initramfs

```bash
cd /path/to/telix

# Merge T2's rootfs into Telix's initramfs/
# This is additive; doesn't clobber Telix's own binaries.
TELIX_T2_HOME=~/src/t2sde \
TELIX_T2_BUILD=telix-min \
tools/t2/install-into-initramfs.sh

# Rebuild the cpio
tools/make-initramfs.sh

# Build and boot
tools/build-kernel.sh x86_64 --release
tools/boot-h14.sh
```

**Result:** Telix boots with `/bin/bash`, `/bin/ls`, `/bin/vi`, libc, and zlib available from T2, layered on top of Telix's own kernel + core servers.

## Non-Interactive Customization (After Bootstrap)

Once `config/telix-min/config` exists, you can tweak it without the TUI:

```bash
cd "$TELIX_T2_HOME"

# Update config via command-line args (sed-based)
./t2 config -cfg telix-min target=tlx-min SDECFGSET_LIBC=musl

# Rebuild (only changed packages are recompiled)
./t2 build -cfg telix-min
```

**Caveats:**
- Args-mode only works on already-populated configs.
- Complex cascading rules (e.g., target-specific arch constraints) are bypassed; use the TUI if uncertain.

## Performance Tuning Knobs

### Build Caching & Parallelism

T2 respects standard environment variables:

```bash
# Parallel build (default: 1 CPU per recipe)
export T2_JOBS=8  # or $(nproc)

# Download cache (keep sources across rebuilds)
export T2_DOWNLOAD_CACHE=~/t2-downloads

# Compiler cache (gccache-like for C objects)
export T2_CCACHE=1
export CCACHE_DIR=~/t2-ccache
```

### Rebuild Strategies

- **Incremental:** `./t2 build -cfg telix-min` (only rebuilds changed packages)
- **Clean:** `./t2 build -cfg telix-min --force` (full rebuild)
- **Specific package:** `./t2 build -cfg telix-min -pkg bash` (just bash)

### Disk Space

- Checkout: ~200MB
- First build (with toolchain): ~500MB–2GB (temp build dirs)
- Final artifact: ~80MB (rootfs tree)
- Keep: `build/telix-min-*/rootfs/` (payload); can delete intermediate obj dirs

## Known Gotchas & Workarounds

### 1. Interactive Bootstrap Unavoidable

The `Create-Config` helper (if it exists in T2) is intended for programmatic config modification *after* initial creation, not bootstrap. There is no documented way to seed a fresh config from a template without human intervention. **Workaround:** Automate everything else; accept the ~30-second TUI step.

### 2. Args-Mode Silent Failures

If you run `./t2 config -cfg nonexistent key=val`, the script silently succeeds without creating anything. **Workaround:** Always verify the config exists (`ls config/$NAME/config`) before relying on args-mode edits.

### 3. Package Names vs. Config Knobs

T2's package set (`pkgsel`) is separate from the config file. Changing it requires either:
- Editing `config/telix-min/../pkgsel` directly (underscores, no SDECFGSET_ prefix), or
- Using the TUI to toggle packages (slower but safer).

**Example:** To add dropbear:
```bash
echo "[O] payload = dropbear" >> config/telix-min/../pkgsel
```
Then rebuild.

### 4. Libc Exit Cleanup Crash (glibc)

Per `project_ld_debug_libc_pf`, glibc's `__intl_freemem` can crash on exit under certain debug settings. **Workaround:** Switch to musl if LD_DEBUG is needed, or add `_exit(0)` early in init code.

### 5. Cross-Compilation Requires Architecture Selection

If building for aarch64 on x86_64, the TUI will ask for architecture *after* target selection. You must:
1. Use the TUI to pick aarch64 (cannot be preset in args-mode).
2. Set `SDECFGSET_CROSSBUILD=1` in config.in to enable cross-compiler build.

## Checking Out a Specific T2 Version

For reproducibility, pin T2 to a known tag:

```bash
cd ~/src/t2sde
git fetch --depth=1 origin tag <TAG>
git checkout <TAG>
```

Current recommended: main branch (latest stable). No formal Telix-tested version exists yet (scheduled for post-Phase-172).

## Future Automation Possibilities

- **Config templating:** Contribute a `T2_CONFIG_SEED` env var to T2 (upstream feature request). Would allow `./t2 config -cfg new --seed=tlx-min` to copy-and-tweak an existing config.
- **Headless TUI:** Use T2's Lua-based config introspection to programmatically walk the menu without ncurses (advanced, maintainer-heavy).
- **Pre-generate config at sync time:** Store a post-bootstrap snapshot of `config/telix-min/config` in Telix's tree; symlink it during sync to bypass the TUI on subsequent clones.

For now, accept the interactive step and document it clearly in CI/CD scripts.

## Verification Checklist

After setup, before first build:

```bash
# 1. T2 checkout exists and is valid
[ -d "$TELIX_T2_HOME/target/tlx-min" ] && echo "tlx-min target synced"

# 2. Config bootstrapped
[ -f "$TELIX_T2_HOME/config/telix-min/config" ] && echo "config exists"

# 3. Check arch and libc
grep "SDECFGSET_ARCH" "$TELIX_T2_HOME/config/telix-min/config"
grep "SDECFGSET_LIBC" "$TELIX_T2_HOME/config/telix-min/config"

# 4. Prerequisite tools available
which gcc make ar cpp
pkg-config --exists ncurses && echo "ncurses OK"
```
